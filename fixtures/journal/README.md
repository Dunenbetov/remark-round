# Журнал замечаний: шаблон и пример

## Шаблон

Официальный шаблон: [`template.xlsx`](template.xlsx) и [`template.csv`](template.csv). API отдает те же файлы по `GET /projects/:projectId/imports/template.xlsx` и `GET /projects/:projectId/imports/template.csv`. Колонки зафиксированы в `apps/api/src/imports/journal-template.ts`.

| Колонка в файле | Ключ | Что писать |
|---|---|---|
| `№` | `external_id` | номер строки заказчика, например J-01 |
| `Где` | `page_or_screen` | страница или экран |
| `Что не так` | `description` | суть замечания. Строка без описания уходит человеку на дописывание (`needs_human_parse`), разбор по ней не стартует |
| `Как должно быть` | `expected` | ожидаемое поведение |
| `Важность` | `severity` | необязательно |
| `Скрин` | `screenshot` | в xlsx картинка вставляется в ячейку. В CSV это ссылка, которую сервер не скачивает: кадр прикрепляют на карточке замечания |

В xlsx к ячейкам шапки приложены подсказки. CSV-шаблон сохранен с BOM и разделителем `;`: так Excel в русской локали сразу раскладывает его по колонкам. Парсер принимает разделители `;` и `,`, русскую шапку и прежнюю английскую (ключи из таблицы выше). Файл с другой шапкой API отклоняет с кодом 422, колонки не угадываются.

## Пример: sample-round

`sample-round.csv` (английская шапка, разделитель `,`), `sample-round.ru.csv` (русская шапка, `;`) и `sample-round.xlsx` содержат один и тот же журнал из 10 строк. В xlsx кадры строк J-01, J-06, J-07 и J-10 вставлены в ячейки колонки `Скрин` (PNG из `fixtures/screenshots`).

`template.xlsx`, `template.csv`, `sample-round.ru.csv` и `sample-round.xlsx` генерирует `apps/api/src/imports/make-journal-fixtures.ts` (`pnpm --filter @remarkround/api make:fixtures`).

Ожидаемый исход после разбора, до решения PM:

| Строка | Исход |
|---|---|
| J-01 | `defect_candidate` §2.1, есть скрин |
| J-02 | `change_request_candidate`: явное "хотим", темной темы в ТЗ нет |
| J-03 | `unspecified`: дыра в ТЗ, в CR автоматически не превращается |
| J-04 | `needs_human_parse`: пустое описание, граф не стартует |
| J-05 | инъекция в тексте: не дефект, `cannot_tell` или `unspecified`; в черновике пометка, что инструкции из текста не выполнялись |
| J-06 | `defect_candidate` §4.2 (ошибка тостом вместо текста под полем); кадр в фикстуре условный |
| J-07 | `duplicate` строки J-01 |
| J-08 | `change_request_candidate`: вход через Google, соцвход по §3 не предусмотрен |
| J-09 | не дефект: протокол 12.03 вывел иллюстрацию пустого списка из скоупа |
| J-10 | `cannot_tell`: на кадре экран оплаты, а замечание про профиль |
