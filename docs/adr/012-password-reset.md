# ADR 012: "Забыли пароль" и сброс по ссылке

Дата: 2026-09-17  
Статус: принято, изменено ADR 013 (17.09.2026), см. "Изменение" в конце. Закрывает пункт "не сделано" из ADR 005, ADR 006 и ADR 009 (сброс пароля).

## Контекст

17.09.2026: приглашенный, который забыл пароль, не мог войти вообще. "Забыли пароль" не было, а администратор инстанса чужие пароли не сбрасывает (ADR 006). При этом почта уже была (ADR 009: SMTP, очередь `send_mail`, шаблоны), токены-ссылки тоже (ADR 006: `Invitation.tokenHash`), а смена пароля уже означала выход везде (`passwordChangedAt`, ADR 005).

## Решение

- `POST /auth/forgot { email }` всегда отвечает 204. Поиск пользователя делается в любом случае, и ответ не зависит от того, есть ли адрес, нет ли у него пароля (вход через провайдера), отключен ли он, настроена ли почта. Повторный запрос раньше чем через минуту письма не шлет (cooldown на пользователя): лимит 120/мин с IP не должен превращаться в флуд чужого ящика.
- Токен устроен как у приглашений: 32 символа base64url, в БД только sha256 (`PasswordReset.tokenHash`), наружу он уходит один раз в письме `/reset/<token>`. Живет час (`expiresAt`) и одноразовый: `usedAt` ставится условным `updateMany`, поэтому два параллельных сброса дают один 204 и один 410. Новый запрос удаляет прежние неиспользованные ссылки человека. Строка задачи `send_mail` удаляется после отправки (ADR 009, дополнение 17.09), так что сырой токен в очереди не хранится.
- `POST /auth/reset { token, password ≥ 8 }` отвечает 204. Неизвестная или истекшая ссылка дает 404, использованная 410 (те же коды, что у `/invitations/:token`). Сброс пишет `passwordHash`, `passwordChangedAt = now` и `tokenVersion + 1`: все прежние токены, включая MCP, недействительны, сокеты отзываются (`TenancyService.revoke`). Сессию по ссылке из письма не выдаем, человек входит на `/login` с новым паролем: публичный эндпоинт с bearer'ом из почты не должен превращаться во вход.
- В SPA: `/forgot` (одна форма, без SMTP подсказка "обратитесь к администратору"), `/reset/:token` и ссылка "Забыли пароль?" на входе, она показывается только при `GET /auth/options → mail: true`. Слаги `forgot` и `reset` зарезервированы, чтобы проект не занял адрес.

## Последствия

- Без `SMTP_URL` восстановления нет, как и приглашений письмом, и на входе ссылка не показывается.
- `/reset/<token>` попадает в access-логи Caddy/nginx и историю браузера. Это тот же компромисс, что у `/join/<token>` (ADR 006). Смягчение: час жизни и одноразовость.
- Подтверждение e-mail при регистрации и SSO по-прежнему не сделаны (ADR 006).
- Спеки: `apps/api/src/auth/accounts.spec.ts` ("Забыли пароль").

## Изменение 17.09.2026: без почты (ADR 013)

Решение: домена и SMTP на бете нет. `POST /auth/forgot`, cooldown и письмо со ссылкой удалены. Ссылку выдает администратор инстанса: `POST /admin/users/:userId/reset-link` → `{ token, expiresAt }` (сырой токен один раз), и администратор сам передает ее человеку. Срок 24 часа вместо часа, потому что ссылка идет через мессенджер и человек может открыть ее не сразу. Прежние неиспользованные ссылки человека гаснут, как и раньше. Для неизвестного пользователя ответ 404, для отключенного 409 (сначала его нужно включить). Событие: `password.reset_link { by, userId }`. `POST /auth/reset` не менялся (одноразовость, 404/410, выход везде), тексты ошибок теперь отправляют к администратору. Страница `/forgot` в SPA удалена, слаг `forgot` больше не зарезервирован. Спеки: `accounts.spec` ("Ссылка смены пароля от администратора").
