# ADR 012 — «Забыли пароль»: ссылка письмом на час, сброс = выход везде

Дата: 2026-09-17  
Статус: принято. Закрывает пункт «не сделано» из ADR 005, ADR 006 и ADR 009 (сброс пароля).

## Контекст

Ревью беты (17.09.2026, I-5): приглашённый, который забыл пароль, не мог войти вообще — «забыли пароль» не было, а администратор инстанса чужие пароли не сбрасывает (ADR 006, A-5). Почта уже есть (ADR 009: SMTP, очередь `send_mail`, шаблоны), токены-ссылки уже есть (ADR 006: `Invitation.tokenHash`), смена пароля уже означает выход везде (`passwordChangedAt`, ADR 005).

## Решение

- **`POST /auth/forgot { email }` → всегда 204.** Поиск пользователя делается в любом случае; ответ не зависит от того, есть ли адрес, нет ли у него пароля (вход через провайдера), отключён ли он, настроена ли почта. Повторный запрос раньше минуты письма не шлёт (cooldown на пользователя): лимит 120/мин с IP не должен превращаться в флуд чужого ящика.
- **Токен — как у приглашений**: 32 символа base64url, в БД только sha256 (`PasswordReset.tokenHash`), наружу один раз в письме `/reset/<token>`. Живёт **час** (`expiresAt`), одноразовый (`usedAt` ставится условным `updateMany` — два параллельных сброса дают один 204 и один 410); новый запрос удаляет прежние неиспользованные ссылки человека. Строка задачи `send_mail` удаляется после отправки (ADR 009, дополнение 17.09) — сырой токен не хранится в очереди.
- **`POST /auth/reset { token, password ≥ 8 }` → 204.** Неизвестная или истёкшая ссылка — 404, использованная — 410 (те же коды, что у `/invitations/:token`). Сброс пишет `passwordHash`, `passwordChangedAt = now` и `tokenVersion + 1`: все прежние токены, включая MCP, недействительны, сокеты отзываются (`TenancyService.revoke`). Сессию по ссылке из письма **не выдаём** — человек входит на `/login` с новым паролем (публичный эндпоинт с bearer'ом из почты не должен превращаться во вход).
- **SPA**: `/forgot` (одна форма; без SMTP — подсказка «обратитесь к администратору»), `/reset/:token`, ссылка «Забыли пароль?» на входе — только при `GET /auth/options → mail: true`. Слаги `forgot` и `reset` зарезервированы, чтобы проект не занял адрес.

## Последствия

- Без `SMTP_URL` восстановления нет — как и приглашений письмом; на входе ссылка не показывается.
- `/reset/<token>` попадает в access-логи Caddy/nginx и историю браузера — тот же компромисс, что у `/join/<token>` (ADR 006), смягчение — час жизни и одноразовость.
- Подтверждение e-mail при регистрации и SSO по-прежнему не сделаны (ADR 006).
- Спеки: `apps/api/src/auth/accounts.spec.ts` («Забыли пароль»).
