# ADR 015: Выбор LLM (OpenAI, Claude, Gemini, локальная модель)

Дата: 2026-09-19 (записано задним числом: модели выбраны 03.09, живые замеры 04.09)  
Статус: принято, уточнено по замерам 20-21.09 (см. "Дополнение 21.09.2026" в конце)

## Контекст

Что нужно от модели на шагах графа ([GRAPH.md](../GRAPH.md)):

- картинки: факты кадра на триаже и три кадра на ретесте (было, стало, дифф), причем на дешевой модели, потому что vision зовется на каждом замечании с кадром;
- строгий JSON: класс только из пяти, номера опор, исход ретеста только из трех, без невалидного JSON и классов вне списка;
- стрим абзаца для PM;
- русский язык в замечаниях, ТЗ и ответах;
- эмбеддинги для поиска по пакету документов;
- цена: замечания идут десятками за раунд, у проекта суточный лимит расходов.

Стек проекта допускал официальные SDK OpenAI или Anthropic.

## Что стоит сейчас

По коду: `apps/api/src/llm/openai-triage-llm.ts`, `llm-params.ts`, `embeddings.service.ts`.

| Шаг | Вызов | Модель | temperature | max_tokens |
|---|---|---|---|---|
| факты кадра | `visionFacts` | `gpt-4.1-mini` (`LLM_MODEL_FAST`) | 0 | 160 |
| переписать запрос | `rewriteQuery` | `gpt-4.1-mini` | 0 | 60 |
| класс и опоры | `classify`, JSON-схема `strict: true` | `gpt-4.1-mini` | 0 | 300 |

| ретест без диффа, только A/B | `retestJudge`, JSON-схема | `gpt-4.1-mini` | 0 | 200 |

`top_p` не передается: OpenAI советует менять либо temperature, либо top_p. Картинки передаются с `detail: auto`. Переключатели для экспериментов (`LLM_TEMP_CLASSIFY`, `LLM_TEMP_DRAFT`, `LLM_TOP_P`, `LLM_MAX_TOKENS_DRAFT`, `LLM_IMAGE_DETAIL`, `SKILL_DISABLED`, `VISION_DISABLED`) без значения поведение не меняют (`llm-params.ts`). Цены из `apps/api/src/llm/pricing.ts`, тариф Standard, сверены 18.09.2026 со страницей developers.openai.com/api/docs/pricing. USD за 1M токенов:

## Альтернативы

Оценивали по документации, на нашем golden не проверяли.

- Claude (Anthropic). Чат и картинки есть. Своих эмбеддингов у Anthropic нет, документация Anthropic отсылает к Voyage AI (platform.claude.com, раздел Embeddings, проверено 18.09). Значит, для поиска нужны второй поставщик и второй договор по данным.
- Gemini (Google). По документации есть картинки, ответ по JSON-схеме (подмножество JSON Schema), эмбеддинги и OpenAI-совместимый адрес API (ai.google.dev, проверено 18.09). По функциям подходит. Качество на русских замечаниях и строгость схемы на нашем golden не проверяли.
- Локальная модель. Railway запускает только CPU, GPU нет (docs.railway.com, проверено 18.09). Модель с картинками и русским языком пришлось бы держать на своем GPU-сервере вне нашего прода. Это имеет смысл, когда данные не должны покидать контур компании (см. "Когда пересмотреть").

Цены конкурентов не приводим: с официальными страницами их не сверяли.

## Решение

Один поставщик, OpenAI, официальный SDK `openai`. Две модели по ролям: дешевая `gpt-4.1-mini` там, где ответ является ярлыком, JSON или фактами кадра, и сильная `gpt-4.1` только на абзаце, который читает человек. Эмбеддинги: `text-embedding-3-small`.

Почему один поставщик: чат, картинки на дешевой модели, эмбеддинги и строгая JSON-схема (`response_format: json_schema`, `strict: true`) у одного поставщика означают один ключ, один счет, один договор по данным и одну обертку трейсинга (`observeOpenAI` из `@langfuse/openai`).

## Что измеряли и что нет

Замеры описаны в `docs/EVALS.md`. Первые живые прогоны были 04.09.2026 на `gpt-4.1-mini` + `gpt-4.1`, golden из 30 кейсов триажа и 13 кейсов ретеста:

- три итерации промпта classify: binding 22 → 23 → 25 из 30, faithfulness 29 → 30 → 30 из 30, в среднем 5,0 с на замечание (граф шел мимо очереди);
- A/B ретеста: pixel-diff + пояснение против "два кадра в модель", по 12/13, но одно ложное "исправлено" только у второго варианта. Победитель стоит в коде по умолчанию (ADR 002).

Стоимость в тех отчетах завышена: `gpt-4.1-mini` считалась по цене `gpt-4.1` из-за ошибки поиска ключа в `pricing.ts`, исправлена 18.09 (`pricing.spec.ts`). Обе цены mini ровно в 5 раз ниже, поэтому ретест (только mini) был завышен ровно в 5 раз, триаж меньше. Верные цифры сняты в замерах 20.09 на коммите `f106d0d`: разбор $0,0033 и 3,8 с p50, ретест $0,0007. Таблица моделей (все на `gpt-4.1`, fast = nano, черновик на mini): `docs/EVALS.md`, раздел 5. Вывод по черновику: дополнение 21.09 ниже.

Другого поставщика на golden не мерили, в замерах 20-21.09 его тоже нет: для этого нужна своя реализация `TriageLlm`.

План замеров из первой редакции этого ADR выполнен 20.09 на коммите `f106d0d`, результаты в `docs/EVALS.md`:

- другие модели OpenAI (все на `gpt-4.1`, `gpt-4.1-nano` на быстрых шагах, `gpt-4.1-mini` на черновике): [EVALS](../EVALS.md), раздел 5, вывод в дополнении 21.09 ниже;
- temperature, top_p, max_tokens и `detail` картинок: EVALS, разделы 4 и 6. Результаты в пределах разброса. Черновик метрики не видят, его температура выбрана заранее;
- вклад Skill и vision (`SKILL_DISABLED`, `VISION_DISABLED`): EVALS, раздел 6. Абляция картинки оказалась нечистой, вклад картинки там разобран по кейсам;
- режим правил с настоящими эмбеддингами: 17 из 33 (EVALS, раздел 2).

Не измеряли модели других поставщиков и семейство `gpt-5`.

### Почему не `gpt-5`

По документации OpenAI семейство `gpt-5` относится к reasoning-моделям: у них есть параметр `reasoning.effort`, токены рассуждения входят в лимит выхода и в расход, а меньший effort ускоряет ответ и снижает расход (developers.openai.com, guides/reasoning и API reference, проверено 24.09). Наши лимиты выхода (60-300 токенов) и температуры заданы под ответ без рассуждения, их пришлось бы подбирать заново. Качество, цену и задержку `gpt-5` на golden не мерили. Для перехода нужны правка параметров вызова в `openai-triage-llm.ts` и прогон golden, как для любой другой модели.

## Данные

Тексты замечаний, фрагменты ТЗ и кадры уходят в OpenAI, а вместе с трейсами и в Langfuse Cloud (EU). С 21.09 на проде рабочие проекты моей команды. Маскирования персональных данных нет, это сознательное решение для своей команды. Правило проекта для компании: боевые персональные данные в облако без договора не отправлять. При переезде в контур компании решение пересматривается.

## Где граница поставщика в коде

- `apps/api/src/llm/triage-llm.ts`: контракт `TriageLlm` (шесть вызовов, учет токенов, признак `canSee`). Граф знает только его. Реализации: `OpenAiTriageLlm`, `RulesTriageLlm` без модели, `FakeLlmService` в тестах.
- `apps/api/src/llm/openai-triage-llm.ts`: единственная реализация на OpenAI. В ней промпты, JSON-схемы, стрим с `include_usage`, картинки как `image_url` с `detail`, `max_tokens`.
- `apps/api/src/llm/llm.service.ts` выбирает реализацию на старте. `openai-client.ts` создает клиент, `llm-errors.ts` переводит ошибки SDK OpenAI в коды очереди, в `pricing.ts` лежат цены, в `llm-params.ts` параметры.
- `apps/api/src/llm/embeddings.service.ts`: модель и размерность эмбеддингов. Миграция `20260903000000_chunk_embedding_vector_1536`: колонка `vector(1536)` и индекс HNSW.
- `apps/api/src/observability/observability.service.ts`: обертка `observeOpenAI` для трейсов.

Что придется менять при замене:

- Чат-модель другого поставщика: новая реализация `TriageLlm` (у каждого поставщика свой формат JSON-схем, картинок, стрима и учета токенов), разбор ошибок в `llm-errors.ts`, цены в `pricing.ts`, обертка трейсов, затем прогон golden. Ноды графа, ворота faithfulness и Skill не меняются.
- Эмбеддинги: новый `EmbeddingsService`, переиндексация всех документов всех проектов, перекалибровка порогов `BOUND_SCORE = 0.45` и `GAP_SCORE = 0.28` (подобраны на близостях `text-embedding-3-small`), прогон `rag:eval` и evals. Если размерность не 1536, нужна еще миграция колонки и индекса. Смешивать векторы разных моделей в одном индексе нельзя.
- Другая модель OpenAI: переменные `LLM_MODEL_FAST` / `LLM_MODEL_STRONG` и прогон evals, для семейства `gpt-5` еще и параметры вызова.

## Последствия

- Одна точка отказа: при полном отказе OpenAI не работают ни модель, ни поиск (эмбеддинги). Очередь повторяет прогоны через 30 с, 2 мин и 8 мин. Ручной режим правил (`LLM_MODE=rules`) спасает только от отказа chat-моделей. Автоматического перехода на вторую модель или поставщика нет, это сознательное решение (`docs/ARCHITECTURE.md`, "Стоимость, латентность, fallback").
- Смена цен OpenAI требует правки `pricing.ts`. Модель без прайса считается как $0: суточный лимит ее не видит, в лог пишется предупреждение.
- Главные гарантии держит код: фильтр проекта в SQL, дефект только с цитатой, ворота faithfulness, закрывает только человек. Слабая модель ухудшит ярлыки, безопасность от нее не зависит.

## Когда пересмотреть

- Итоги замеров 20-21.09: если `gpt-4.1-mini` на черновике не хуже `gpt-4.1`, черновик переводится на mini; если hit@k покажет проблемы поиска, сравниваются модели эмбеддингов.
- OpenAI меняет цены, или расход проекта регулярно упирается в `GRAPH_DAILY_USD_PER_PROJECT`.
- При переезде в контур компании данные не должны покидать контур, или нужен договор с конкретным поставщиком. Варианты: облачная модель по договору (в SDK OpenAI есть клиент для Azure OpenAI), другой поставщик по договору или своя модель на GPU-сервере компании за тем же `TriageLlm`. Выбор делается прогоном golden.
- Отказы OpenAI дольше окна повторов (около 10 минут) становятся регулярными. Тогда нужна запасная модель или поставщик за тем же контрактом.
- OpenAI снимает модели `gpt-4.1` с поддержки.

## Дополнение 21.09.2026: черновик остается на `gpt-4.1`

Пункт "Итоги замеров 20-21.09" из раздела "Когда пересмотреть" проверен. По метрикам golden `gpt-4.1-mini` в черновике не хуже (`evals/results/2026-09-20-model-draft-mini.md`: опора 29/33, честность 33/33 при базе 28-29/33 и 33/33) и вдвое дешевле: $0,0017 против $0,0033 за замечание. Но тексты черновиков обеих моделей по тем же 33 замечаниям (Langfuse Cloud) показали у mini 4 фактические ошибки из 33: трижды "протокол от 11.03" вместо 12.03 (дата демо из текста протокола) и один раз неправда заказчика (подпись "Отправить") перенесена в описание кадра, где на самом деле "Сохранить". У `gpt-4.1` таких ошибок нет. Черновик является главным текстом, по которому PM принимает решение, а экономия составляет около $0,50 в месяц при 300 замечаниях. Но для человека это не единственный текст: пояснение ретеста на mini читает заказчик, и там mini в 13 пояснениях из 24 с исходом "похоже, исправлено" пишет "претензия решена" или "устранена" (`docs/EVALS.md`, раздел 7). Решение владельца 21.09: черновик остается на `gpt-4.1`, остальные шаги на `gpt-4.1-mini`, как было.

Остальные модели из замеров 20-21.09:

- `gpt-4.1` в быстрых шагах: опора 27/33, цена ×2, но ретест 14/15 без ложных "исправлено". Пояснение ретеста на ней занимает 6,3 с p50 против 1,2 с у mini, на нее пояснение не переключали.
- `gpt-4.1-nano` отвергнута: 22/33, ломает повторы и защиту от инъекций.

Подробно: `docs/EVALS.md`, разделы 5 и 13.
