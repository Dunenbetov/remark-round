# ADR 015 — Выбор LLM: OpenAI, а не Claude / Gemini / локальная модель; когда пересмотреть

Дата: 2026-09-19 (записано задним числом: модели выбраны 03.09, живые замеры — 04.09)  
Статус: принято; уточнено по замерам M1 20–21.09 — см. «Дополнение 21.09» в конце

## Контекст

Что нужно от модели на шагах графа ([GRAPH.md](../GRAPH.md)):

- **картинки** — факты кадра на триаже и три кадра на ретесте (было, стало, дифф), причём на дешёвой модели: vision зовётся на каждом замечании с кадром;
- **строгий JSON** — класс только из пяти, номера опор, исход ретеста только из трёх; без невалидного JSON и классов вне списка;
- **стрим** абзаца для PM;
- **русский язык** в замечаниях, ТЗ и ответах;
- **эмбеддинги** для поиска по пакету документов;
- **цена** — замечания идут десятками за раунд, у проекта суточный лимит расходов.

Доктрина допускала официальные SDK OpenAI или Anthropic (`REMARKROUND.md` §5).

## Что стоит сейчас

По коду: `apps/api/src/llm/openai-triage-llm.ts`, `llm-params.ts`, `embeddings.service.ts`.

| Шаг | Вызов | Модель | temperature | max_tokens |
|---|---|---|---|---|
| факты кадра | `visionFacts` | `gpt-4.1-mini` (`LLM_MODEL_FAST`) | 0 | 160 |
| переписать запрос | `rewriteQuery` | `gpt-4.1-mini` | 0 | 60 |
| класс и опоры | `classify`, JSON-схема `strict: true` | `gpt-4.1-mini` | 0 | 300 |
| абзац для PM | `draft`, стрим | `gpt-4.1` (`LLM_MODEL_STRONG`) | 0.3 | 220 |
| пояснение ретеста | `retestExplain`, JSON-схема | `gpt-4.1-mini` | 0 | 200 |
| ретест без диффа, только A/B | `retestJudge`, JSON-схема | `gpt-4.1-mini` | 0 | 200 |
| поиск | эмбеддинги | `text-embedding-3-small`, 1536 измерений | — | — |

`top_p` не передаётся: OpenAI советует менять либо temperature, либо top_p. Картинки — `detail: auto`. Переключатели для экспериментов (`LLM_TEMP_CLASSIFY`, `LLM_TEMP_DRAFT`, `LLM_TOP_P`, `LLM_MAX_TOKENS_DRAFT`, `LLM_IMAGE_DETAIL`, `SKILL_DISABLED`, `VISION_DISABLED`) без значения поведение не меняют (`llm-params.ts`). Клиент SDK: таймаут 60 с, 2 повтора (`apps/api/src/llm/openai-client.ts`).

Цены из `apps/api/src/llm/pricing.ts` — тариф Standard, сверены 18.09.2026 со страницей developers.openai.com/api/docs/pricing; USD за 1M токенов:

| Модель | Вход | Выход |
|---|---|---|
| `gpt-4.1` | 2 | 8 |
| `gpt-4.1-mini` | 0.4 | 1.6 |
| `gpt-4.1-nano` | 0.1 | 0.4 |
| `text-embedding-3-small` | 0.02 | — |

Скидку за кэшированный вход не учитываем. В `pricing.ts` есть и семейства `gpt-4o`, `gpt-5`; вызов с `gpt-5` не проверяли — reasoning-модели ждут `max_completion_tokens` и температуру по умолчанию.

## Решение

Один поставщик — OpenAI, официальный SDK `openai`, две модели по ролям: дешёвая `gpt-4.1-mini` там, где ответ — ярлык, JSON или факты кадра; сильная `gpt-4.1` только на абзаце, который читает человек. Эмбеддинги — `text-embedding-3-small`.

Почему один поставщик: чат, картинки на дешёвой модели, эмбеддинги и строгая JSON-схема (`response_format: json_schema`, `strict: true`) — это один ключ, один счёт, один договор по данным и одна обёртка трейсинга (`observeOpenAI` из `@langfuse/openai`).

Альтернативы оценивали по документации, на нашем golden **не проверяли**:

- **Claude (Anthropic).** Чат и картинки есть. Своих эмбеддингов у Anthropic нет, документация Anthropic отсылает к Voyage AI (platform.claude.com, раздел Embeddings, проверено 18.09). Значит, второй поставщик для поиска и второй договор по данным.
- **Gemini (Google).** По документации есть картинки, ответ по JSON-схеме (подмножество JSON Schema), эмбеддинги и OpenAI-совместимый адрес API (ai.google.dev, проверено 18.09). По функциям подходит; качество на русских замечаниях и строгость схемы на нашем golden не проверяли.
- **Локальная модель.** Railway запускает только CPU, GPU нет (docs.railway.com, проверено 18.09). Модель с картинками и русским языком пришлось бы держать на своём GPU-сервере вне нашего прода. Это имеет смысл, когда данные не должны покидать контур компании — см. «Когда пересмотреть».

Цены конкурентов не приводим: с официальными страницами их не сверяли.

## Что измеряли и что нет

Измеряли — `docs/EVALS.md`, живые прогоны 04.09.2026 на `gpt-4.1-mini` + `gpt-4.1`, golden из 30 кейсов триажа и 13 кейсов ретеста:

- три итерации промпта classify: binding 22 → 23 → 25 из 30, faithfulness 29 → 30 → 30 из 30, в среднем 5,0 с на замечание (граф шёл мимо очереди);
- A/B ретеста: pixel-diff + пояснение против «два кадра в модель» — по 12/13, но только у второго варианта одно ложное «исправлено»; победитель стоит в коде по умолчанию (ADR 002).

Стоимость в тех отчётах завышена: `gpt-4.1-mini` считалась по цене `gpt-4.1` — ошибка поиска ключа в `pricing.ts`, исправлена 18.09 (P3, `pricing.spec.ts`). Обе цены mini ровно в 5 раз ниже, поэтому ретест (только mini) был завышен ровно в 5 раз, триаж — меньше. Верные цифры — после M1.

Другого поставщика на golden не мерили, и в M1 его нет: для этого нужна своя реализация `TriageLlm`.

Не измеряли, это список замеров M1 (`docs/defense/M1-COMMANDS.md`):

- другие модели OpenAI: всё на `gpt-4.1`, `gpt-4.1-nano` на быстрых шагах, `gpt-4.1-mini` на черновике. Черновик на `gpt-4.1`, вероятно, главная статья цены разбора, а нужна ли там сильная модель, цифрой не подтверждено;
- temperature, top_p, max_tokens и `detail` картинок: обоснование по формату ответа есть, таблицы экспериментов нет;
- вклад Skill и vision (`SKILL_DISABLED`, `VISION_DISABLED`);
- режим правил с настоящими эмбеддингами.

Результаты M1 лягут в `docs/EVALS.md` с датой и git sha; выводы этого ADR сверим с ними.

## Данные

Тексты замечаний, фрагменты ТЗ и кадры уходят в OpenAI, а вместе с трейсами — в Langfuse Cloud (EU). С 21.09 на проде будут рабочие проекты команды владельца. Это решение владельца; маскирования персональных данных нет. Доктрина для компании: боевые персональные данные в облако без договора не слать (`REMARKROUND.md` §12). При переезде в контур компании решение пересматривается.

## Где граница поставщика в коде

- `apps/api/src/llm/triage-llm.ts` — контракт `TriageLlm` (шесть вызовов, учёт токенов, признак `canSee`). Граф знает только его. Реализации: `OpenAiTriageLlm`, `RulesTriageLlm` без модели, `FakeLlmService` в тестах.
- `apps/api/src/llm/openai-triage-llm.ts` — единственная реализация на OpenAI: промпты, JSON-схемы, стрим с `include_usage`, картинки как `image_url` с `detail`, `max_tokens`.
- `apps/api/src/llm/llm.service.ts` выбирает реализацию на старте; `openai-client.ts` — клиент; `llm-errors.ts` переводит ошибки SDK OpenAI в коды очереди; `pricing.ts` — цены; `llm-params.ts` — параметры.
- `apps/api/src/llm/embeddings.service.ts` — модель и размерность эмбеддингов; миграция `20260903000000_chunk_embedding_vector_1536` — колонка `vector(1536)` и индекс HNSW.
- `apps/api/src/observability/observability.service.ts` — обёртка `observeOpenAI` для трейсов.

Что придётся менять при замене:

- **Чат-модель другого поставщика:** новая реализация `TriageLlm` (у каждого поставщика свой формат JSON-схем, картинок, стрима и учёта токенов), разбор ошибок в `llm-errors.ts`, цены в `pricing.ts`, обёртка трейсов, затем прогон golden. Ноды графа, ворота faithfulness и Skill не меняются.
- **Эмбеддинги:** новый `EmbeddingsService`, переиндексация всех документов всех проектов, перекалибровка порогов `BOUND_SCORE = 0.45` и `GAP_SCORE = 0.28` (подобраны на близостях `text-embedding-3-small`), прогон `rag:eval` и evals. Если размерность не 1536 — ещё миграция колонки и индекса. Смешивать векторы разных моделей в одном индексе нельзя.
- **Другая модель OpenAI:** переменные `LLM_MODEL_FAST` / `LLM_MODEL_STRONG` и прогон evals; для семейства `gpt-5` — ещё параметры вызова.

## Последствия

- Одна точка отказа: при полном отказе OpenAI не работают ни модель, ни поиск (эмбеддинги). Очередь повторяет прогоны через 30 с, 2 мин и 8 мин; ручной режим правил (`LLM_MODE=rules`) спасает только от отказа chat-моделей. Автоматического перехода на вторую модель или поставщика нет — сознательно (`docs/ARCHITECTURE.md`, «Стоимость, латентность, fallback»).
- Смена цен OpenAI требует правки `pricing.ts`. Модель без прайса считается как $0 — суточный лимит её не видит, в лог пишется предупреждение.
- Главные гарантии держит код, а не модель: фильтр проекта в SQL, дефект только с цитатой, ворота faithfulness, закрывает только человек. Слабая модель ухудшит ярлыки, но не безопасность.

## Когда пересмотреть

- **Итоги M1.** Если `gpt-4.1-mini` на черновике не хуже `gpt-4.1` — перевести черновик на mini. Если hit@k покажет проблемы поиска — сравнить модели эмбеддингов.
- **Цены.** OpenAI меняет цены, или расход проекта регулярно упирается в `GRAPH_DAILY_USD_PER_PROJECT`.
- **Требования к данным при переезде в контур компании владельца:** данные не должны покидать контур или нужен договор с конкретным поставщиком. Варианты — облачная модель по договору (в SDK OpenAI есть клиент для Azure OpenAI), другой поставщик по договору или своя модель на GPU-сервере компании за тем же `TriageLlm`. Выбор — прогоном golden.
- **Доступность.** Отказы OpenAI дольше окна повторов (около 10 минут) станут регулярными — добавить запасную модель или поставщика за тем же контрактом.
- **Модели `gpt-4.1` снимут с поддержки.**

## Дополнение 21.09.2026 — итоги M1: черновик остаётся на `gpt-4.1`

Пункт «Итоги M1» из «Когда пересмотреть» проверен. По метрикам golden `gpt-4.1-mini` в черновике не хуже (`evals/results/2026-09-20-model-draft-mini.md`: опора 29/33, честность 33/33 при базе 28–29/33 и 33/33) и вдвое дешевле: $0,0017 против $0,0033 за замечание. Но тексты черновиков обеих моделей по тем же 33 замечаниям (Langfuse Cloud) показали у mini 4 фактические ошибки из 33: трижды «протокол от 11.03» вместо 12.03 (дата демо из текста протокола), один раз неправда заказчика («подпись «Отправить»») перенесена в описание кадра, где на самом деле «Сохранить». У `gpt-4.1` таких ошибок нет. Черновик — единственный текст, который читает человек, а экономия — около $0,50 в месяц при 300 замечаниях. **Решение владельца 21.09: черновик остаётся на `gpt-4.1`**, остальные шаги — на `gpt-4.1-mini`, как было.

Остальные модели M1: `gpt-4.1` в быстрых шагах — опора 27/33, цена ×2, но ретест 14/15 без ложных «исправлено» (кандидат только для ретеста); `gpt-4.1-nano` — отказ: 22/33, ломает повторы и защиту от инъекций. Подробно — `docs/EVALS.md` и [`docs/defense/HONEST-NOTES.md`](../defense/HONEST-NOTES.md), п. 2.
