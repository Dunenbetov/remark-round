# ADR 010 — Закрыть без нового кадра: заказчик проверил сам; вернуть — только с кадром

Дата: 2026-09-13  
Статус: принято

## Контекст

Владелец, 13 сентября 2026: «Разработчик исправил — бизнес проверил, претензия исчерпана — можно закрыть без доказательного скрина. Незачем затягивать очевидные вещи». До этого закрыть замечание можно было только из `awaiting_business_close`, а попасть туда — только через новый кадр, pixel-diff и пояснение модели (ADR 002). Заказчик, который уже видит на стенде, что кнопка синяя, должен был сделать скриншот, дождаться сравнения и лишь потом нажать «Закрыть: исправлено».

Доктрина (REMARKROUND.md §2.1 п.3) запрещала утверждать «исправлено» без нового кадра. Этот запрет написан против **системы**: модель по двум картинкам не судит, «исправлено» от LLM без диффа — брак. Судья же — человек, и закрытие делает только заказчик, сторона, которая выдвинула претензию.

## Решение

- **`ready_for_retest → closed` — только роль `business`**, сразу после «Готово» разработчика. `POST …/remarks/:id/close` принимает `{ comment? }` (до 2000 символов) и из `awaiting_business_close` (после ретеста), и из `ready_for_retest` (проверил сам). Пока идёт сравнение кадров — 409.
- **Закрытие без кадра — признание заказчика, а не утверждение системы.** Граф в этом переходе не участвует; модель, ноды ретеста, MCP и evals не меняются: система по-прежнему никогда не ставит `closed` и не говорит «исправлено» без диффа.
- **«Не исправлено» — только с новым кадром**, как было: вернуть разработчику значит спорить с «Готово», и спор ведётся уликой, а не словами. Из `ready_for_retest` `not-fixed` отвечает 409 «сначала прикрепите кадр ретеста».
- **Как закрыли — видно всегда.** Отдельного поля нет: строка истории `close` хранит `fromStatus` (`ready_for_retest` — «проверено заказчиком, без нового кадра», `awaiting_business_close` — «после ретеста: новый кадр и дифф»), кто закрыл, в какой роли, когда и комментарий. Карточка отдаёт `closedVia` и `closeComment`. Закрыть можно один раз (`closed` терминален, повтор претензии — новое замечание), так что строка `close` одна.
- В интерфейсе заказчика режим `retest-check`: «Закрыть: исправлено» (клавиша 1, пять секунд на «Отменить», комментарий по желанию), «Не исправлено» серая, рядом дропзона нового кадра — сравнение остаётся для спорных случаев.

## Последствия

- В STATUS.md появился переход `ready_for_retest → closed`; письмо заказчику после «Готово» — «проверьте: закройте или приложите новый кадр».
- Раунд закрывается быстрее: `ready_for_retest` больше не требует круга ретеста.
- Если заказчик через год скажет «не сделали», ответом служит его же закрытие: имя, роль, дата и время, комментарий (ADR 011 — история, которую нельзя переписать).
- Не сделано: комментарий к «Не исправлено» без кадра (владелец выбрал кадр); WS-событие для других открытых вкладок — карточка обновится при следующем чтении, как и после «Готово» разработчика.
