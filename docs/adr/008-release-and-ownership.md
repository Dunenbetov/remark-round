# ADR 008: Релизный контур (образы из CI, версия на сервере, откат по тегу) и права на код

Дата: 2026-09-07  
Статус: принято

## Контекст

Аудит 6 сентября 2026 показал: прод собирался прямо на боевом сервере (`up -d --build` на 2 vCPU), у сборок не было ни тегов, ни реестра, узнать, какая версия на сервере, было нельзя, откат означал пересборку под нагрузкой, миграции применялись при каждом старте под `restart: always`. У репозитория не было ни `LICENSE`, ни поля `license`, а юрист компании не может принять код с неопределенным правообладателем.

## Решение

- Образы собирает CI. Job `images` в `.github/workflows/ci.yml` на push в `main` и на тег `v*` публикует `ghcr.io/<owner>/remark-round-{api,web,mcp}` с тегами `sha-<short>`, `<git-tag>` и `latest` (только `main`). На сервере сборки нет. `ARG GIT_SHA` → `ENV APP_VERSION` в образе, `GET /api/v1/health` отдает `version`, фронт отдает `/version.txt`.
- Прод поднимает образ по тегу: `RR_TAG=sha-abc1234` в `.env`, `docker compose pull && up -d`. Демо и dev собирают локально под тем же именем (`RR_TAG=local`).
- Миграции в проде идут отдельным шагом (`MIGRATE_ON_START=false`): `docker compose run --rm api migrate` после бэкапа и до `up`. При старте API только проверяет `migrate status` и падает с понятной ошибкой, если что-то не применено. Демо-стенд по-прежнему мигрирует сам.
- Откат делается другим `RR_TAG` и `pull && up`, без сборки. Данные возвращаются restore дампа: миграции Prisma forward-only, и перед миграцией с потерей данных обязательна репетиция на копии.
- Версии: `git tag vX.Y.Z` при каждом выкате в компанию. `CHANGELOG` не ведем, пока релизов меньше одного в неделю: хватает истории коммитов и тегов.
- Права на код: в `LICENSE` проприетарная запись, правообладателем указан автор, `license: UNLICENSED` во всех `package.json`. Передача прав или лицензия компании оформляется договором, файлом в репозитории этот вопрос не решается. До договора код используется в компании по устной договоренности пилота, и до раскатки ее нужно закрепить письменно.

## Последствия

- Первый выкат на чистый сервер: `.env` → `docker compose pull` → `docker compose run --rm api migrate` → `up -d`. Без `ADMIN_EMAILS`, секретов Langfuse и `POSTGRES_PASSWORD` compose не стартует.
- `pnpm audit --prod --audit-level=high` входит в CI обязательным шагом. Транзитивные уязвимости с патчем закрыты `pnpm.overrides` в корневом `package.json`. Dependabot раз в неделю обновляет npm, базовые образы и actions (`.github/dependabot.yml`). Secret scanning и Dependabot alerts включаются в настройках репозитория.
- Копию вне сервера делает сервис `offsite` (профиль `offsite`): раз в сутки `rclone sync` дампов и тома `api-storage` в S3-совместимое хранилище, healthcheck помечает копию старше 36 часов как unhealthy. Восстановление репетируется по `docs/PROD.md` до первого пилота и потом раз в квартал.
- Не сделано: staging-окружение и smoke-тест перед промоушеном, multi-stage Dockerfile и образ без devDependencies, автоматический деплой на сервер (деплой идет руками по runbook, осознанно, пока сервер один).
