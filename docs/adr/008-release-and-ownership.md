# ADR 008 — Релизный контур: образы из CI, версия на сервере, откат по тегу; права на код

Дата: 2026-09-07  
Статус: принято

## Контекст

Аудит (6 сентября 2026): прод собирался прямо на боевом сервере (`up -d --build` на 2 vCPU), у сборок не было ни тегов, ни реестра, «какая версия на сервере» было не узнать, откат означал пересборку под нагрузкой, миграции применялись при каждом старте под `restart: always`, а у репозитория не было ни `LICENSE`, ни поля `license` — юрист компании не может принять код с неопределённым правообладателем.

## Решение

- **Образы собирает CI**, не сервер: job `images` в `.github/workflows/ci.yml` на push в `main` и на тег `v*` публикует `ghcr.io/<owner>/remark-round-{api,web,mcp}` с тегами `sha-<short>`, `<git-tag>` и `latest` (только `main`). `ARG GIT_SHA` → `ENV APP_VERSION` в образе; `GET /api/v1/health` отдаёт `version`, фронт — `/version.txt`.
- **Прод поднимает образ по тегу**: `RR_TAG=sha-abc1234` в `.env`, `docker compose pull && up -d`. Демо и dev собирают локально под тем же именем (`RR_TAG=local`).
- **Миграции — отдельный шаг** в проде (`MIGRATE_ON_START=false`): `docker compose run --rm api migrate` после бэкапа и до `up`; при старте API только проверяет `migrate status` и падает с понятной ошибкой, если что-то не применено. Демо-стенд по-прежнему мигрирует сам.
- **Откат = другой `RR_TAG` + `pull && up`**, без сборки. Данные — restore дампа (миграции Prisma forward-only; перед миграцией с потерей данных — обязательная репетиция на копии).
- **Версии**: `git tag vX.Y.Z` при каждом выкате в компанию; `CHANGELOG` не заводим, пока релизов меньше одного в неделю — история коммитов и теги достаточны.
- **Права на код**: `LICENSE` — проприетарная запись, правообладатель — автор; `license: UNLICENSED` во всех `package.json`. Решение о передаче прав или лицензии компании — договор, не файл в репозитории; до него код используется в компании по устной договорённости пилота, что нужно закрыть письменно до раскатки (аудит: no-license).

## Последствия

- Первый выкат на чистый сервер: `.env` → `docker compose pull` → `docker compose run --rm api migrate` → `up -d`. Без `ADMIN_EMAILS`, секретов Langfuse и `POSTGRES_PASSWORD` compose не стартует.
- `pnpm audit --prod --audit-level=high` — обязательный шаг CI; транзитивные уязвимости с патчем закрыты `pnpm.overrides` в корневом `package.json`; Dependabot раз в неделю обновляет npm, базовые образы и actions (`.github/dependabot.yml`). Secret scanning и Dependabot alerts включаются в настройках репозитория.
- Копия вне сервера — сервис `offsite` (профиль `offsite`, `rclone sync` дампов и тома `api-storage` в S3-совместимое хранилище раз в сутки, healthcheck «копия старше 36 часов — unhealthy»). Восстановление репетируется по `docs/PROD.md` до первого пилота и потом раз в квартал.
- Не сделано здесь: staging-окружение и smoke-тест перед промоушеном (before_scale), multi-stage Dockerfile и образ без devDependencies (before_scale), автоматический деплой на сервер (руками по runbook — осознанно, пока сервер один).
