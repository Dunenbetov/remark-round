# ADR 003: MCP как фасад домена

Дата: 2026-08-20, разделы "Альтернативы" и "Как сделано" дописаны 19.09.2026  
Статус: принято

## Контекст

Курс требует свой MCP-сервер с 2-3 содержательными tool'ами. REST при этом уже есть, и MCP должен давать что-то сверх него. Писать в БД только через MCP из графа было бы искусственно и вредно для прода.

## Альтернативы

### Только REST

REST остается главным API, через него работает Angular. Но REST рассчитан на код, который заранее написал программист: он решает, какой запрос и когда отправить. У MCP другой потребитель, ИИ-ассистент в редакторе, который сам решает, что вызвать. Ему MCP дает то, чего нет в REST:

- Клиент при подключении запрашивает `tools/list` и получает имена, описания и JSON-схемы параметров, поэтому интеграцию под каждого клиента писать не нужно. Cursor, Claude Code или Claude Desktop подключаются одним JSON-конфигом: в репозитории лежат `.mcp.json` (Claude Code) и `.cursor/mcp.json` (Cursor), пример для Claude Desktop есть в `apps/mcp/README.md`.
- Правила домена приходят вместе с инструментами. `instructions` сервера и описания tool'ов говорят ассистенту: не выдумывай номера разделов, цитируй только то, что `search_spec` отметил как опору, решение PM записывай только по явному слову человека, закрыть замечание через MCP нельзя (`apps/mcp/src/server.ts`). Читающие tool'ы помечены `readOnlyHint`.
- Prompt `uat-triage` отдает текст `skills/uat-triage/SKILL.md`, ту же процедуру, что стоит в системном промпте графа ([GRAPH.md](../GRAPH.md), "Skill").
- PM в редакторе спрашивает "что в ТЗ сказано про эту кнопку?" или "что ждет решения?" и записывает решение. Заказчик отправляет локальный скриншот на ретест. Разработчику доступны поиск по ТЗ и его очередь. Все это без браузера и с теми же правами, что в интерфейсе: решение записывает только PM, ретест отправляет только заказчик.

### Граф как клиент MCP

Граф живет в том же процессе, что и доменные сервисы, и зовет их напрямую (`apps/api/src/agent/graph-deps.ts`). Ходить к самому себе по сетевому протоколу значит добавить задержку и точку отказа, а единственный путь записи уже есть: `RemarksService`. Общее у MCP с остальным проектом: тот же JWT и те же guards, тот же `SKILL.md`, сборка и тест в CI, сервис в `docker compose`.

### MCP со своей логикой

Второй бэкенд означал бы второй путь записи, вторую авторизацию и второй тест на утечку между проектами. Поэтому своей бизнес-логики у фасада нет намеренно.

## Решение

- В БД пишут только доменные сервисы Nest.
- REST и граф вызывают сервисы.
- `apps/mcp` служит тонким фасадом тех же REST-маршрутов для ИИ-ассистента в IDE (Cursor, Claude Code, Claude Desktop).
- Auth: токен с `projectId` из membership. Tool не принимает чужой проект "по просьбе модели".

Tool'ы: `search_spec`, `get_round_remarks`, `apply_human_verdict`, `submit_retest_evidence`, плюс prompt `uat-triage`.

## Как сделано (19.09.2026)

- Фасад остается тонким адаптером. Сверх REST он добавляет немного клея: последний раунд и фильтр по статусу в `get_round_remarks`, проверку статуса и подстановку `runId` и ключа идемпотентности в `apply_human_verdict`, загрузку локального файла в `submit_retest_evidence`. Еще он отвечает модели текстом и переводит ошибки HTTP на язык домена.
- Транспортов два (`apps/mcp/src/main.ts`). stdio по умолчанию: IDE сама запускает процесс на машине пользователя, и tool может прочитать локальный файл кадра. Streamable HTTP без сессий: токен в заголовке `Authorization` каждого запроса, локальные файлы выключены, в `docker-compose.yml` адрес `127.0.0.1:3002`. HTTP-вариант отдельным тестом не покрыт.
- `POST /projects/:projectId/mcp-token` выдает JWT с `projectId` из membership на 30 дней (`MCP_TOKEN_EXPIRES_SECONDS`, `apps/api/src/config.ts:17`). С ним API отдает 404 на любой другой проект и на все вне `/projects/:projectId/*`. Токен ограничивает только проект: внутри проекта напрямую через REST он может то же, что роль. Отозвать один токен нельзя. Доступ снимают смена пароля, "Завершить сессии" у администратора, отключение пользователя или удаление из проекта.
- `search_spec` берет порог графа `BOUND_SCORE` (0.45) из поля `boundScore` ответа `GET …/search` (у API без этого поля запасные 0.45). Фрагменты ниже порога фасад помечает "опорой считать нельзя", а если выше порога ничего нет, отвечает "Опоры нет" и фрагментов не показывает. Внешний канал строже графа: в графе порог решает только, переписывать ли запрос, а classify может сослаться и на фрагмент ниже порога ([GRAPH.md](../GRAPH.md), "Роль `bind_to_clause` в боевом режиме").
- На Railway MCP не поднят, так решено: он нужен тем, кто работает из редактора, продукт без него полон. Если он понадобится, инструкция есть в `docs/PROD-RAILWAY.md`, раздел "MCP (по желанию)".
- Тест `apps/api/src/mcp/mcp.facade.spec.ts` поднимает настоящий процесс `apps/mcp` по stdio и подключается официальным клиентом MCP, как это делает IDE.

## Последствия

Внутри MCP нельзя использовать `prisma` и нельзя делать echo-tools. Tool'а закрытия нет и не будет: закрывает заказчик кнопкой в интерфейсе.
