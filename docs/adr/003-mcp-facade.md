# ADR 003 — MCP это фасад домена, не второй CRUD

Дата: 2026-08-20; разделы «Почему MCP, а не REST» и «Как сделано» дописаны 19.09.2026  
Статус: принято

## Контекст

Курс требует свой MCP-сервер с 2–3 содержательными tool'ами. Возражение комиссии: «зачем протокол, если есть REST». Писать в БД только через MCP из графа — искусственно и вредно для прода.

## Решение

- Единственная запись: доменные сервисы Nest.
- REST и граф вызывают сервисы.
- `apps/mcp` — тонкий фасад тех же REST-маршрутов для ИИ-агента в IDE (Cursor, Claude Code, Claude Desktop).
- Auth: токен с `projectId` из membership. Tool не принимает чужой проект «по просьбе модели».

Tool'ы: `search_spec`, `get_round_remarks`, `apply_human_verdict`, `submit_retest_evidence`; плюс prompt `uat-triage`.

## Почему MCP, а не REST

REST остаётся главным API: через него работает Angular. Но REST рассчитан на код, который заранее написал программист, — он решает, какой запрос и когда отправить. У MCP другой потребитель: ИИ-агент в редакторе, который сам решает, что вызвать.

- **Инструменты находятся без клея.** При подключении клиент запрашивает `tools/list` и получает имена, описания и JSON-схемы параметров. Писать интеграцию под каждого клиента не нужно: Cursor, Claude Code или Claude Desktop подключаются одним JSON-конфигом: в репозитории лежат `.mcp.json` (Claude Code) и `.cursor/mcp.json` (Cursor), пример для Claude Desktop — в `apps/mcp/README.md`.
- **Правила домена приходят вместе с инструментами.** `instructions` сервера и описания tool'ов говорят агенту: не выдумывай номера разделов, цитируй только то, что `search_spec` отметил как опору; решение PM записывай только по явному слову человека; закрыть замечание через MCP нельзя (`apps/mcp/src/server.ts`). Читающие tool'ы помечены `readOnlyHint`.
- **Общий Skill.** Prompt `uat-triage` отдаёт текст `skills/uat-triage/SKILL.md` — ту же процедуру, что стоит в системном промпте графа ([GRAPH.md](../GRAPH.md), «Skill»).
- **Сценарий.** PM в редакторе спрашивает «что в ТЗ сказано про эту кнопку?» или «что ждёт решения?» и записывает решение; заказчик отправляет локальный скриншот на ретест; разработчику доступны поиск по ТЗ и его очередь — всё без браузера. Права те же, что в интерфейсе: решение записывает только PM, ретест отправляет только заказчик.

**Почему наш граф не клиент MCP.** Граф живёт в том же процессе, что и доменные сервисы, и зовёт их напрямую (`apps/api/src/agent/graph-deps.ts`). Ходить к самому себе по сетевому протоколу — лишняя задержка и лишняя точка отказа, а единственный путь записи уже есть: `RemarksService`. Общее у MCP с остальным проектом — тот же JWT и те же guards, тот же `SKILL.md`, сборка и тест в CI, сервис в `docker compose`.

**Честно:** это тонкий адаптер без своей бизнес-логики. Сверх REST он добавляет немного клея: последний раунд и фильтр по статусу в `get_round_remarks`, проверку статуса и подстановку `runId` и ключа идемпотентности в `apply_human_verdict`, загрузку локального файла в `submit_retest_evidence`. Ещё он отвечает модели текстом и переводит ошибки HTTP на язык домена. Своей логики у фасада нет намеренно: второй бэкенд означал бы второй путь записи, вторую авторизацию и второй тест на утечку между проектами.

## Как сделано (19.09.2026)

- **Два транспорта** (`apps/mcp/src/main.ts`). stdio по умолчанию: IDE сама запускает процесс на машине пользователя, и tool может прочитать локальный файл кадра. Streamable HTTP без сессий: токен в заголовке `Authorization` каждого запроса, локальные файлы выключены; в `docker-compose.yml` — на `127.0.0.1:3002`. HTTP-вариант отдельным тестом не покрыт.
- **Токен.** `POST /projects/:projectId/mcp-token` выдаёт JWT с `projectId` из membership, срок — 30 дней (`MCP_TOKEN_EXPIRES_SECONDS`, `apps/api/src/config.ts:17`). С ним API отдаёт 404 на любой другой проект и на всё вне `/projects/:projectId/*`. Токен ограничивает проект, а не действия: напрямую через REST он может внутри проекта то же, что роль. Отозвать один токен нельзя: доступ снимают смена пароля, «Завершить сессии» у администратора, отключение пользователя или удаление из проекта.
- **Порог опоры в `search_spec`.** Фасад берёт порог графа `BOUND_SCORE` (0.45) из поля `boundScore` ответа `GET …/search` (у API без этого поля — запасные 0.45): фрагменты ниже порога помечает «опорой считать нельзя», а если выше порога ничего нет — отвечает «Опоры нет» и фрагментов не показывает. Внешний канал строже графа: в графе порог решает только, переписывать ли запрос, а classify может сослаться и на фрагмент ниже порога ([GRAPH.md](../GRAPH.md), «Роль `bind_to_clause` в боевом режиме»).
- **На Railway не поднят** — решение: MCP нужен тем, кто работает из редактора, продукт без него полон. Если понадобится — `docs/PROD-RAILWAY.md`, «MCP (по желанию)».
- **Тест:** `apps/api/src/mcp/mcp.facade.spec.ts` поднимает настоящий процесс `apps/mcp` по stdio и подключается официальным клиентом MCP — делает то же, что IDE.

## Последствия

Нельзя `prisma` внутри MCP. Нельзя echo-tools. Tool'а закрытия нет и не будет: закрывает заказчик кнопкой в интерфейсе. На защите MCP показывают не из Angular, а из IDE. Зачем MCP: работа с приёмкой из редактора по тому же контракту и с теми же правами.
