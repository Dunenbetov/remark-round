## 0. Что проектируем

Спроектируй UI веб-приложения RemarkRound: слой приёмки веб-проекта в компании заказной разработки. Заказчик (бизнес) присылает замечания к сделанному сайту. По каждому замечанию система собирает опору: скриншот, цитата из ТЗ или протокола, черновик разбора. Затем человек, руководитель приёмки, нажимает одну кнопку: это поломка, новое желание, дыра в документах или мало данных. Разработчик получает только принятые поломки. Ретест: новый скрин, пиксельный дифф, закрывает только бизнес.

Это не трекер задач, не чат с ИИ, не админка. Метафора: стол с бумагами и снимками экрана, над которым парит стеклянная панель управления. Главный экран: карточка замечания. Экраны будут показывать с проектора на защите, читаемость важнее плотности.

Язык интерфейса: русский. Все подписи ниже дословно, синонимы запрещены.

## 1. Материал и настроение

Два слоя, и их нельзя путать.

Бумага (контент): тёплый матовый фон, непрозрачные карточки. Здесь живут скрин, цитаты, таблица, текст черновика. Никакого стекла под текстом контента.

Стекло (управление): панели в духе Apple Liquid Glass поверх бумаги. Только: липкая шапка с ролью, липкая группа кнопок решения, фазовая строка, тулбар полноэкранного просмотра кадра, пилюля присутствия. Стекло означает «что можно нажать» и «что происходит прямо сейчас». Не больше трёх стеклянных элементов на экране одновременно.

Спецификация стекла: фон rgba(255,253,248,0.78), backdrop-filter blur(24px) saturate(140%), внешняя граница 1px rgba(31,27,22,0.08), внутренний блик 1px по верхнему краю rgba(255,255,255,0.65), тень 0 8px 32px rgba(31,27,22,0.10), радиус 16px для панелей и 999px для пилюль. Стекло тёплое, почти белое. Без радужного преломления, без цветных бликов, без синих и фиолетовых градиентов. Текст на стекле обязан проходить контраст 4.5:1; если не проходит, стекло делается плотнее, текст не темнеет.

Только светлая тема. Тёмная в этом продукте запрещена.

## 2. Система

Цвета (CSS-переменные, использовать как есть):
--rr-bg #f3eee6 (фон; допустим radial-gradient к #efe6d6 из левого верхнего угла), --rr-surface #fffdf8, --rr-surface-2 #f8f3ea, --rr-ink #1f1b16, --rr-ink-soft #5c564e, --rr-line #e4d9c8, --rr-accent #1f4a3c (единственный primary, глубокий зелёный), --rr-accent-hover #16382d, --rr-wait #b8893a (ждёт человека), --rr-work #2b5578 (в работе), --rr-muted #8a847a (желание, дыра, повтор), --rr-ok #2f6b4f (закрыто), --rr-danger #8f3a30 (только «допишите строку» и маска диффа).

Типографика: IBM Plex Sans 400/500/600. Source Serif 4 600 только для слова RemarkRound. Шкала: роль в шапке 22/28 600; заголовки колонок карточки 12/16 600 uppercase, letter-spacing .06em, цвет ink-soft; основной текст 14/20; метаданные 13/18 ink-soft; цитата ТЗ 15/22 500 ink; номера замечаний tabular-nums. Минимальный размер текста на экране 13px.

Форма: радиус 12px у карточек, 10px у кнопок, 999px у чипов и статусов. Сетка 8pt. Контентная ширина 1180–1280px. Колонки карточки 1.15fr / 1fr / 0.85fr. Одна тень на всё приложение: 0 10px 40px rgba(31,27,22,0.06). Иконки: тонкие 1.5px линейные, только там, где без них хуже. Никаких эмодзи и звёздочек-искр.

Компоненты для артборда «Система»:
- Кнопка primary: заливка accent, белый текст 600, высота 40, радиус 10.
- Кнопка вторичная: прозрачная, граница 1px line, текст ink, выравнивание влево. Кнопки решения стоят списком сверху вниз, не рядом.
- Фокус: видимое кольцо 2px accent с отступом 2px.
- Чип-фильтр: граница 1px line; активный: граница accent, фон #edf4f1, текст accent.
- Статус-пилюля, фон и текст: wait #f8edd6 / #8a5b12; work #e4eef6 / #2b5578; muted #eeeae3 / #8a847a; ok #e3efe8 / #2f6b4f; danger #f6e3e0 / #8f3a30.
- Цитата из документа: слева полоса 3px accent, отступ 12px, заголовок «В ТЗ (§2.1):» 600, сам текст в кавычках «…», под ним текстовая ссылка «Открыть документ» 13px accent.
- Фазовая строка: стекло, высота 36, слева точка 6px цвета wait с мягкой пульсацией 1.2s, текст 13px ink-soft.
- Пилюля присутствия: стекло, инициалы в кружке 20px, текст «Смотрит: Айгерим · принимает работу».
- Стеклянная шапка: липкая, 64–72px. Слева роль крупно, под ней «Клиентский кабинет · Раунд 2». По центру навигация-пилюли: Документы · Журнал · Импорт (у разработчика вместо них одна: В работу). Справа: пилюля присутствия и инициалы пользователя. У бизнеса справа ещё primary-кнопка «Добавить замечание».

## 5. Живое поведение (показать состояниями, не роликом)

- Фазовая строка меняет текст: Смотрим документы проекта… → Смотрим скрин… → Ищем место в ТЗ… → Готовим черновик… → Ждём вашего решения. Переход 150–200ms fade. Без шиммера, без градиентной волны, без скелетонов на полкарточки.
- Черновик печатается только внутри блока «Черновик разбора», по словам, без курсора.
- Пилюля присутствия появляется и исчезает за 150ms.
- «Не та цитата из ТЗ» с комментарием: кнопки гаснут, фаза «Ищем другое место в ТЗ…», старая цитата уходит, новая появляется. Та же карточка, без перезагрузки.
- Ошибка: фазовая строка «Не получилось разобрать. Можно запустить снова» и текстовая кнопка «Запустить снова». Не тост.
- Чужой проект: экран без данных и надпись «Нет доступа». Без объяснений.

## 7. Тест готовности

Бухгалтер, увидев карточку впервые, за 30 секунд понимает: что на картинке, где это в ТЗ, какую одну кнопку нажать. Всё читается с проектора с пяти метров. Если экран похож на Linear, Jira или ChatGPT, это провал, переделать.
