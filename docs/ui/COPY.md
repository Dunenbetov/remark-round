# COPY.md — священный словарь UI

Копировать **дословно**. Не заменять на Approve, Reject, Submit, Ticket, Copilot.  
Язык продукта: русский. Коды статусов (`defect`) — только в API и `data-status`.

## Роли в шапке (крупно, всегда видно)

| Код | Шапка |
|---|---|
| `business` | Вы принимаете работу |
| `pm` | Вы решаете, работа ли это |
| `developer` | Вам передали в работу |
| `admin` | Настройка проекта |

Рядом мелко: название проекта · Раунд N.

## Кнопки PM на карточке (порядок сверху вниз)

1. **В работу разработчикам** — primary, решение `defect`
2. **Новое желание, не в этом ТЗ** — `change_request`
3. **В документах нет ответа — решите вы** — `unspecified`
4. **Не хватает скрина** — `cannot_tell`
5. **Не та цитата из ТЗ** — `rejected_binding` (нужен комментарий)

Поле под кнопками: **Комментарий (необязательно, для «не та цитата» — обязательно)**

Разработчик этих кнопок не видит — но пока замечание ждёт PM, он может **посоветовать** теми же формулировками (режим «Ваш совет», eyebrow **Посоветуйте руководителю приёмки**, подпись **Совет — не решение: руководитель приёмки увидит его рядом с вариантом, решает он.**). Совет уходит сразу, без отсчёта: **Ваш совет: В работу разработчикам** · **Изменить** · **Убрать**. У PM у варианта — бейдж **Developer советует** (несколько человек — **2 разработчика советуют**) и строка **Developer советует «В работу разработчикам»: «комментарий»**. После решения PM у разработчика: **Совет совпал ✓** / **Ваш совет был: …**.

## Кнопки бизнеса

| Когда | Текст |
|---|---|
| Новое замечание | **Добавить замечание** |
| На карточке, создать | **Сохранить** |
| Прикрепить кадр | **Прикрепить скрин** |
| Ретест: ок (и сразу после «Готово», если проверили сами — ADR 010) | **Закрыть: исправлено** |
| Ретест: нет (только с новым кадром) | **Не исправлено** |
| Комментарий к закрытию | **Добавить комментарий** → «Комментарий к закрытию (необязательно)» |
| Импорт | **Скачать шаблон журнала** · **Загрузить файл** |

Нет кнопки «Закрыть» у модели и у разработчика.

Под штампом «Закрыто» — как закрыли: **Проверено заказчиком, без нового кадра** или **После ретеста: новый кадр и дифф**, затем комментарий в кавычках. В истории та же строка: «Закрыто без нового кадра: заказчик проверил сам» / «Закрыто после ретеста».

## Кнопки разработчика

| Текст | Действие |
|---|---|
| **Готово, можно смотреть снова** | `ready_for_retest` |
| **Посоветовать** (группа очереди **Сейчас у руководителя приёмки · N**, подсказка **Это ещё не работа: решает руководитель приёмки. Откройте карточку и посоветуйте, что выбрали бы вы.**) | `PUT …/advice` — не переход |

Не «Resolve», не «Done», не «Close». Совет — не «Approve» и не «Vote».

## Колонки карточки

**Замечание · Черновик разбора · Ваше решение** — это шаги строки пути над ними. На ретесте и в ожидании нового кадра левая колонка — **Проверка**. Блок текста заказчика — **Что написал заказчик** (строка из журнала — «Из журнала · J-01»). Не «Улики», не «Дело», не «Вердикт» (ANTI.md).

## Черновик модели (не «чат»)

- Заголовок блока: **Черновик разбора**
- Предложение: **Похоже, это поломка относительно ТЗ** / **Похоже, это новое желание** / **В бумагах нет опоры** / **Похоже на повтор** / **Недостаточно данных**
- Цитата: **В ТЗ (§2.1):** «…»  — клик открывает документ
- Факты кадра: **На скрине видно:** …
- Честный отказ: **Не могу разобрать. Пришлите скрин этого экрана.**
- Ретест, дропзона: **Прикрепите новый кадр этого экрана** · «Того же размера, что первый кадр (1278×535), иначе сравнить не выйдет · перетащите, нажмите или Ctrl+V»; кадры разного размера — «Кадры разного размера: … — пиксели не сопоставить. Приложите кадр того же размера, что первый (…), или, если проверили на стенде, закройте без кадра.» (20.09); другая причина (разбросанные изменения, формат) — «<Причина>. Проверьте на стенде — если всё в порядке, закройте без кадра.» Слово «исправлено» система не пишет — его говорит человек (21.09)
- Цитаты из ТЗ нет: **В ТЗ опоры не нашли: места, которое описывало бы этот экран, в тексте нет.** (20.09)
- Заказчику до решения (ADR 007) вместо черновика и цитат: **Разбор готов и ждёт руководителя приёмки. Что нашли в документах и что решили — появится здесь вместе с решением.**
- Нет строки «уверенность 87%». Нет названия модели.

## Фазы (тонкая строка внизу, не лог IDE)

| Код | Строка |
|---|---|
| `retrieving` | Смотрим документы проекта… |
| `vision` | Смотрим скрин… |
| `binding` | Ищем место в ТЗ… |
| `drafting` | Готовим черновик… |
| `awaiting_pm` | Ждём вашего решения |
| `diffing` | Сравниваем кадры… |
| `awaiting_business_close` | Ждём, подтвердите исправление |
| `ready_for_retest` (заказчику) | Проверьте: закройте или прикрепите новый кадр |
| `ready_for_retest` (остальным) | Ждём проверки заказчика |
| `failed` | Не получилось разобрать. Можно запустить снова |

Стрим текста — только внутри «Черновик разбора», как печать черновика, не как Cursor.

## Списки и фильтры

Фильтры-чипсы (не колонки доски):

- **Ждут меня** — дефолт для PM
- **Все**
- **В работе**
- **Новые желания**
- **На ретесте**
- **Дописать из журнала**

Колонки таблицы раунда: **№ · Суть · Скрин · Черновик · Статус**  
Не: Assignee, Priority, Epic, Updated.

Заголовок дома PM: **Раунд 2 · 12 замечаний, 4 ждут вас**

Очередь dev: **Вам передали в работу** · подзаголовок: «Сюда не попадают желания и дыры в ТЗ, пока руководитель приёмки не решил иначе.»

## Пустые состояния (дословно)

- Нет ТЗ: **Сначала загрузите ТЗ — без него разбирать замечания не будем.**
- Нет замечаний: **Замечаний пока нет. Добавьте с экрана или загрузите журнал по шаблону.**
- Нет скрина у визуальной претензии: **Для претензии про цвет или вёрстку нужен скрин.**
- Импорт: **Эти строки не разобрали. Допишите сами — мы ничего не выдумываем.**
- Очередь dev пуста: **Пока ничего не передали в работу.**
- Чужой проект: не объяснять. Просто нет данных / «Нет доступа».

## Импорт

- **Только наш шаблон.** Другой Excel не угадываем. Шапка шаблона — по-русски: **№ · Где · Что не так · Как должно быть · Важность · Скрин** (в файле и на карточке «Что в шаблоне» одно и то же); ошибка про чужую шапку называет колонки так же.
- Счётчик: **Разобрали 9 из 11. Две строки нужно дописать.**

## Навигация

- **Документы**
- **Журнал** (раунд)
- **Импорт**
- **В работу** (только developer)
- **Добавить замечание**

Не: Board, Issues, Copilot, Inbox как у Linear.

## 30-секундный тест

Человек с бизнеса на карточке понимает: что на картинке, где это в ТЗ, какую **одну** кнопку нажать. Если нет — чини COPY/вёрстку, не добавляй туториал.

## История замечания (ADR 011)

Раздел **История** внизу карточки; на закрытом замечании раскрыт сразу. Строка: дата с годом и время в поясе читателя («10 сент. 2026, 15:10») · имя на момент действия и роль («Дана (руководитель приёмки)»; действие системы — **RemarkRound**) · что сделано · «→ статус», если он сменился · пометка · слова человека в кавычках · кнопка кадра **кадр** / **новый кадр** / **дифф** (заменённый — «· заменён»).

| action | Подпись |
|---|---|
| `create` · `import` · `reopen` | Замечание создано · Импортировано из журнала · Претензия открыта снова |
| `reopened_as` | Претензию предъявили снова (на закрытом оригинале, пометка «Повтор в раунде 3 — № 2») |
| `link_duplicate` | Связано с оригиналом (пометка «Оригинал — № 4») |
| `verdict` · `rejected_binding` | «Решение: В работу разработчикам» (вариант PM) · Не та цитата — разбор снова |
| `ready_for_retest` · `retest` · `retest_result` | Разработчик: готово · Кадр для ретеста приложен · Кадры сравнили |
| `close` | Закрыто после ретеста · из «Можно смотреть снова» — **Закрыто без нового кадра: заказчик проверил сам** |
| `not_fixed` · `cancel` · `run_failed` | Не исправлено — снова в работу · Разбор остановлен · Разбор не удался |

Заказчик не видит в истории, что предлагала модель, и комментарии команды к решениям — только свои слова (ADR 007).
