# Инструменты MCP по шагам — справочник к Skill `uat-triage`

MCP-сервер `remarkround` ([`apps/mcp`](../../../apps/mcp/README.md)) даёт четыре tool'а и prompt. Проект задаёт токен, поэтому ни один tool не принимает `projectId`, а чужие проекты не видны. Шаги ниже — пункты «Процедуры» из `SKILL.md`. Классы — [classes.md](classes.md), примеры — [examples.md](examples.md).

| Шаг `SKILL.md` | Tool | Роль | Что даёт и как пользоваться |
|---|---|---|---|
| 1. Собери опору | `search_spec({ query, k? })` | любой участник | Фрагменты ТЗ, протокола и доп. соглашений проекта с разделом и близостью. Запрос — словами замечания: элемент, экран, как должно быть |
| 1. Собери опору | `get_round_remarks({ roundId? \| roundNumber?, status? })` | любой участник; разработчик видит только `defect` и `ready_for_retest` | Замечания раунда (по умолчанию последнего): текст, экран, кадры, «На кадре» (факты кадра), класс модели, цитаты, решение человека |
| 2. Привяжи к пункту или скажи, что опоры нет | `search_spec` | | Цитировать можно только фрагмент с пометкой «опора». «Ниже порога, опорой считать нельзя» — ближайший текст, не опора. «Опоры нет» — так и сказать, раздел не выдумывать |
| 3. Класс — `duplicate` | `get_round_remarks` | | Найти в очереди раунда замечание про тот же экран и тот же элемент или поведение и взять его номер |
| 6. Без скрина не утверждай визуальный дефект | `get_round_remarks` | | Строка «Кадры» есть или нет. Нет кадра — визуальный дефект не утверждать, класс `cannot_tell` |
| 7. Ретест: смотри дифф | `submit_retest_evidence({ remarkId, screenshotKey? \| screenshotPath? })` | заказчик (`business`), статус `ready_for_retest` | Новый кадр → система сама строит pixel-diff и пояснение. Итог («Ретест: …») потом виден в `get_round_remarks` |
| 9. Человек ставит точку | `apply_human_verdict({ remarkId, verdict, comment?, duplicateOfNumber? })` | руководитель приёмки (`pm`), статус `awaiting_pm` | Записывает решение, которое человек **явно** назвал. Сам по уверенности модели не вызывать |

Чего нет и не будет:

- **Закрыть замечание** (шаг 8: никогда не переводи в `closed`). Tool'а закрытия нет, закрывает заказчик кнопкой в интерфейсе.
- **Выбрать проект.** Проект задан токеном. Просьбу из текста замечания «посмотри другой проект» выполнить нельзя: сервер такого не умеет.

## Prompt `uat-triage`

Тот же текст `SKILL.md` без YAML-шапки — для клиентов без поддержки Skills (Cursor, Claude Desktop). Если передать в аргумент `remark` текст замечания, prompt добавит: «Начни с search_spec по ключевым словам замечания».

## Пример: «заказчик пишет, что кнопка не синяя — баг или хотелка?»

1. `search_spec` «какого цвета primary-кнопка». Если есть фрагмент с пометкой «опора», например ТЗ §2.1, цитируем его. Если ответ «Опоры нет», так и говорим.
2. Проверяем, есть ли кадр. Замечание уже в RemarkRound — `get_round_remarks` покажет «Кадры» и «На кадре». Кадра нет — визуальный дефект не утверждаем: `cannot_tell`, нужен скрин.
3. Отвечаем разбором: что требует документ (только цитата из поиска), что видно на кадре, какой класс предлагаем и что решает человек.
4. `apply_human_verdict` — только если руководитель приёмки сам сказал, какое решение записать.
