# Примеры разбора: справочник к Skill `uat-triage`

Шесть кейсов из golden-набора [`evals/golden.json`](../../../evals/golden.json): по одному на каждый класс и одна ловушка. Вход взят из golden, опора из фикстур проекта "Клиентский кабинет" ([`fixtures/spec/TZ.md`](../../../fixtures/spec/TZ.md), [`fixtures/protocol/PROTOCOL.md`](../../../fixtures/protocol/PROTOCOL.md)). Верным считается класс, который засчитывает golden (`gold.expect`). Определения классов в [classes.md](classes.md), инструменты в [tools.md](tools.md).

Класс в каждом примере остается предложением модели. Решает руководитель приемки кнопкой.

## 1. Поломка с опорой: `defect_candidate`

| Golden | `defect-save-gray` |
|---|---|
| Что не так | Кнопка "Сохранить" серая |
| Как должно быть | Синяя primary-кнопка при заполненных полях |
| Где | Профиль компании |
| Кадр | форма профиля, кнопка "Сохранить" серая |
| Опора | ТЗ §2.1 Primary: primary-кнопка синяя `#0B5FFF`, подпись "Сохранить" на формах профиля и оплаты, на одной форме одна primary |
| Класс | `defect_candidate` |

(а) ТЗ требует синюю primary-кнопку "Сохранить" на форме профиля. (б) На кадре она серая. Документ и прод расходятся, есть цитата и кадр того же экрана. Опору ищет `search_spec` по словам замечания: цвет, primary-кнопка, "Сохранить".

## 2. Новое желание: `change_request_candidate`

| Golden | `cr-dark-theme`, дефектом быть не может (`mustNot`) |
|---|---|
| Что не так | Хотим темную тему |
| Как должно быть | Чтобы ночью не слепило |
| Где | Весь кабинет |
| Кадр | нет |
| Опора | ТЗ §6 "Чего в ТЗ нет (дыры)": в документе нет темной темы, выгрузки реестра в Excel, двухфакторной аутентификации, смены языка |
| Класс | `change_request_candidate` |

Заказчик сам формулирует новое желание ("хотим"), документы его не обещали.

Вопрос о том, чего в ТЗ нет, слабо похож на текст §6. На демо-проекте `search_spec` с запросом `хотим тёмную тему` отвечает "Опоры нет" (лучшая близость 0.27 при пороге 0.45). Класс от этого не меняется: желание высказано явно.

## 3. Дыра в документах: `unspecified`

| Golden | `hole-excel-export`, не change request и не дефект (`mustNot`) |
|---|---|
| Что не так | Нет выгрузки в Excel |
| Как должно быть | Как в старой 1С |
| Где | Список заказов |
| Кадр | нет |
| Опора | тот же ТЗ §6: выгрузки реестра в Excel в документе нет. Там же сказано, что замечания про эти пункты не становятся CR или дефектом автоматически: это `unspecified`, пока не решил человек, или CR, если заказчик явно хочет новое |
| Класс | `unspecified` |

Заказчик констатирует "нет X" и не просит нового. В примере 2 раздел тот же, но там заказчик пишет "хотим".

`search_spec` с запросом `нет выгрузки в Excel` на демо-проекте тоже отвечает "Опоры нет" (0.34). Для этого класса это не помеха: `unspecified` и означает, что в документах ответа нет и решает человек.

## 4. Повтор: `duplicate`

| Golden | `duplicate-color-again` |
|---|---|
| Что не так | Кнопка сохранить не того цвета опять |
| Где | Профиль компании |
| Кадр | нет |
| В раунде уже есть | замечание №1 на экране "Профиль компании": кнопка "Сохранить" серая, должна быть синяя primary-кнопка |
| Опора | замечание №1 того же раунда; у оригинала опора ТЗ §2.1 |
| Класс | `duplicate`, `duplicateOfNumber: 1` |

Тот же экран и тот же элемент (цвет кнопки "Сохранить"), другими словами. Очередь раунда с номерами и экранами отдает `get_round_remarks`, одним `search_spec` повтор не найти.

## 5. Мало данных: `cannot_tell`

| Golden | `visual-no-shot-wrong-color`, дефектом быть не может (`mustNot`) |
|---|---|
| Что не так | Кнопка не того цвета |
| Где | Профиль компании |
| Кадр | нет |
| Опора | ТЗ §2.1 говорит, какой должна быть кнопка. Что сейчас на проде, не видно |
| Класс | `cannot_tell` |

Визуальная претензия пришла без кадра, а без скрина визуальный дефект не утверждается. Решение PM в этом случае: `Не хватает скрина`.

## 6. Ловушка: неверный пересказ ТЗ

| Golden | `false-cite-toast-4-2` |
|---|---|
| Что не так | В ТЗ §4.2 написано показывать ошибку оплаты тостом, а у нас она под полем: дефект |
| Как должно быть | Тост сверху, как в ТЗ |
| Где | Оплата счета |
| Кадр | нет |
| Опора | ТЗ §4.2 Ошибки: текст ошибки платежа показывается под полем, красным, не тостом и не модалкой. Протокол 12.03, п. 2: текст ошибки оплаты как в ТЗ §4.2, под полем |
| Класс | засчитываются `unspecified`, `change_request_candidate` или `cannot_tell`; `defect_candidate` считается провалом |

Кроме класса golden проверяет текст: в разборе не должно быть фразы, будто ТЗ требует тост (`mustNotMatch`).

Это не дефект. (а) ТЗ требует показывать ошибку под полем. (б) По словам заказчика, на проде ошибка под полем. Расхождения нет: заказчик неверно пересказал раздел. Цитировать можно только то, что вернул поиск. Пересказ раздела в тексте замечания цитатой не считается.
